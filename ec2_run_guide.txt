===============================================
  OmniRoute — EC2 Deployment Guide
===============================================

🧱 STEP 0: EC2 INSTANCE CONFIG
───────────────────────────────
  AMI:        Ubuntu 24.04 LTS
  Type:       t2.medium (2 vCPU, 4 GB RAM)
  Storage:    20 GB gp3
  Key Pair:   Create/select an SSH key pair

  Security Group (Inbound Rules):
    ┌──────────┬──────────┬───────────────────────┐
    │ Port     │ Protocol │ Purpose               │
    ├──────────┼──────────┼───────────────────────┤
    │ 22       │ TCP      │ SSH access            │
    └──────────┴──────────┴───────────────────────┘


🚀 STEP 1: Connect & System Update
───────────────────────────────────
ssh -i "your-key.pem" ubuntu@<EC2_PUBLIC_IP>

sudo apt update && sudo apt upgrade -y


🚀 STEP 2: Install Java (Required by Kafka)
────────────────────────────────────────────
sudo apt install openjdk-11-jdk -y
java -version

  ✔ Java 11 / 17 / 21 → ALL OK


🚀 STEP 3: Install System Dependencies (for Python build)
──────────────────────────────────────────────────────────
sudo apt install -y make build-essential libssl-dev zlib1g-dev \
  libbz2-dev libreadline-dev libsqlite3-dev curl llvm \
  libncursesw5-dev xz-utils tk-dev libxml2-dev libxmlsec1-dev \
  libffi-dev liblzma-dev git


🚀 STEP 4: Install Python 3.10 via pyenv
─────────────────────────────────────────
curl https://pyenv.run | bash

# Add pyenv to shell
echo 'export PYENV_ROOT="$HOME/.pyenv"' >> ~/.bashrc
echo 'export PATH="$PYENV_ROOT/bin:$PATH"' >> ~/.bashrc
echo 'eval "$(pyenv init --path)"' >> ~/.bashrc
echo 'eval "$(pyenv init -)"' >> ~/.bashrc

source ~/.bashrc

pyenv install 3.10.14

  ✔ Verify: pyenv versions  →  should list 3.10.14


🚀 STEP 5: Clone the Project
─────────────────────────────
cd ~
git clone https://github.com/Saint-Potato/omniroute.git
cd omniroute


🚀 STEP 6: Set Python Version for the Project
──────────────────────────────────────────────
pyenv local 3.10.14
python --version

  ✔ Must show: Python 3.10.14


🚀 STEP 7: Create Virtual Environment & Activate
─────────────────────────────────────────────────
python -m venv venv
source venv/bin/activate


🚀 STEP 8: Install Required Libraries
──────────────────────────────────────
pip install --upgrade pip
pip install kafka-python==2.0.2 pandas==2.2.2 numpy==1.26.4 pyarrow

  ⚠️  DO NOT run: pip install -r requirements.txt
      (requirements.txt includes Airflow/Spark/FastAPI — not needed on EC2 for streaming)


🚀 STEP 9: Install Kafka
─────────────────────────
cd ~
wget https://archive.apache.org/dist/kafka/3.6.1/kafka_2.13-3.6.1.tgz
tar -xvf kafka_2.13-3.6.1.tgz
mv kafka_2.13-3.6.1 ~/kafka

  ⚠️  Kafka is installed at ~/kafka (NOT inside the git repo to keep the repo clean)


🚀 STEP 10: Install tmux (Manage Multiple Sessions)
────────────────────────────────────────────────────
sudo apt install tmux -y

  Why? You need 4 processes running simultaneously:
    1. Zookeeper    2. Kafka Broker    3. Producer    4. Consumer
  tmux lets you manage all of them in one SSH connection.


🚀 STEP 11: Start Zookeeper
────────────────────────────
tmux new -s zookeeper

cd ~/kafka
bin/zookeeper-server-start.sh config/zookeeper.properties

  ✔ Wait until you see "binding to port 0.0.0.0/0.0.0.0:2181"
  Press Ctrl+B, then D to detach from this tmux pane.


🚀 STEP 12: Start Kafka Broker
───────────────────────────────
tmux new -s kafka

cd ~/kafka
bin/kafka-server-start.sh config/server.properties

  ✔ Wait until you see "started (kafka.server.KafkaServer)"
  Press Ctrl+B, then D to detach.


🚀 STEP 13: Create Kafka Topic
───────────────────────────────
cd ~/kafka
bin/kafka-topics.sh --create \
  --topic vehicle_telemetry_topic \
  --bootstrap-server localhost:9092 \
  --partitions 1 \
  --replication-factor 1

# Verify topic was created:
bin/kafka-topics.sh --list --bootstrap-server localhost:9092

  ✔ Should show: vehicle_telemetry_topic


🚀 STEP 14: Start the Consumer FIRST
─────────────────────────────────────
  ⚠️  IMPORTANT: Start the consumer BEFORE the producer!
      The consumer uses auto_offset_reset="latest", so it will
      ONLY receive messages produced AFTER it connects.

tmux new -s consumer

cd ~/omniroute
source venv/bin/activate
python telemetry_consumer.py

  ✔ Should print: "Starting Kafka Consumer" → "Waiting for messages..."
  Press Ctrl+B, then D to detach.


🚀 STEP 15: Run the Data Pipeline + Telemetry Producer
───────────────────────────────────────────────────────
tmux new -s producer

cd ~/omniroute
source venv/bin/activate
python data_producer_scripts/run_all_producers.py

  👉 This first generates all batch CSV/JSON data files, then asks:
     "Do you want to start telemetry streaming? (y/n)"

  Enter: y

  ✔ Telemetry events will start flowing → consumer will pick them up.


===============================================
  QUICK REFERENCE — tmux Commands
===============================================
  tmux ls                    → List all sessions
  tmux attach -t <name>      → Reattach to a session (e.g., tmux attach -t consumer)
  Ctrl+B, D                  → Detach from current session
  Ctrl+C                     → Stop the running process inside a session


===============================================
  HEALTH CHECKS
===============================================

  # 1. Check all tmux sessions are running:
  tmux ls

  # 2. Check Kafka broker is alive:
  cd ~/kafka
  bin/kafka-topics.sh --list --bootstrap-server localhost:9092

  # 3. Check consumer output:
  tmux attach -t consumer
  # (should see "Wrote X records → ..." messages)

  # 4. Check data files were generated:
  ls ~/omniroute/data/raw/

  # 5. Check telemetry parquet output:
  ls ~/omniroute/data/raw/telemetry/


===============================================
  STOPPING EVERYTHING (Clean Shutdown)
===============================================

  # 1. Stop producer (Ctrl+C in producer tmux)
  tmux attach -t producer
  # Press Ctrl+C

  # 2. Stop consumer
  tmux attach -t consumer
  # Press Ctrl+C

  # 3. Stop Kafka broker
  tmux attach -t kafka
  # Press Ctrl+C  (or use: ~/kafka/bin/kafka-server-stop.sh)

  # 4. Stop Zookeeper
  tmux attach -t zookeeper
  # Press Ctrl+C  (or use: ~/kafka/bin/zookeeper-server-stop.sh)

  # 5. Kill all tmux sessions:
  tmux kill-server


===============================================
  ALTERNATIVE: Using Multiple SSH Terminals
  (Instead of tmux)
===============================================

  If you prefer separate terminal windows instead of tmux,
  open 4 SSH connections to your EC2 instance.

  ┌────────────┬──────────────────────────────────────────────────┐
  │ Terminal   │ What to Run                                      │
  ├────────────┼──────────────────────────────────────────────────┤
  │ Terminal 1 │ Zookeeper                                        │
  │ Terminal 2 │ Kafka Broker                                     │
  │ Terminal 3 │ Consumer                                         │
  │ Terminal 4 │ Producer (batch data + telemetry streaming)       │
  └────────────┴──────────────────────────────────────────────────┘

  ─── Terminal 1 (Zookeeper) ───
  ssh -i "your-key.pem" ubuntu@<EC2_PUBLIC_IP>

  cd ~/kafka
  bin/zookeeper-server-start.sh config/zookeeper.properties

  ✔ Wait for "binding to port 0.0.0.0/0.0.0.0:2181"
  ⚠️ Keep this terminal open — do NOT close it.


  ─── Terminal 2 (Kafka Broker) ───
  ssh -i "your-key.pem" ubuntu@<EC2_PUBLIC_IP>

  cd ~/kafka
  bin/kafka-server-start.sh config/server.properties

  ✔ Wait for "started (kafka.server.KafkaServer)"
  ⚠️ Keep this terminal open — do NOT close it.


  ─── Terminal 3 (Consumer) ───
  ssh -i "your-key.pem" ubuntu@<EC2_PUBLIC_IP>

  cd ~/omniroute
  source venv/bin/activate
  python telemetry_consumer.py

  ✔ Wait for "Waiting for messages..."
  ⚠️ Start this BEFORE the producer (Step 4 below).


  ─── Terminal 4 (Producer) ───
  ssh -i "your-key.pem" ubuntu@<EC2_PUBLIC_IP>

  cd ~/omniroute
  source venv/bin/activate
  python data_producer_scripts/run_all_producers.py

  👉 Enter: y  (when asked to start telemetry streaming)

  ✔ Events will now flow: Producer → Kafka → Consumer → Parquet files


  ─── Stopping (Multiple Terminals) ───
  Press Ctrl+C in each terminal in this order:
    1. Terminal 4 (Producer)
    2. Terminal 3 (Consumer)
    3. Terminal 2 (Kafka Broker)
    4. Terminal 1 (Zookeeper)

  ⚠️ IMPORTANT: If you close a terminal window without Ctrl+C,
     the process keeps running as an orphan. Kill it with:
     ps aux | grep kafka    → find the PID → kill -9 <PID>
     ps aux | grep python   → find the PID → kill -9 <PID>


===============================================
  RE-RUN GUIDE: Running the Pipeline Again
  (2nd time onwards — everything is installed)
===============================================

  You do NOT need to repeat Steps 0–9 (install Java, pyenv,
  Kafka, pip packages, etc). Those are one-time setup.

  Just follow these steps:

  ── Step A: SSH into EC2 ──
  ssh -i "your-key.pem" ubuntu@<EC2_PUBLIC_IP>


  ── Step B: (Optional) Clean old telemetry data ──
  If you want fresh data (remove old parquet files):

  rm -rf ~/omniroute/data/raw/telemetry/*

  If you also want to regenerate batch CSVs:

  rm -rf ~/omniroute/data/raw/*.csv
  rm -rf ~/omniroute/data/raw/*.json


  ── Step C: (Optional) Pull latest code ──
  cd ~/omniroute
  git pull origin main


  ── Step D: Start Zookeeper ──
  tmux new -s zookeeper
  cd ~/kafka
  bin/zookeeper-server-start.sh config/zookeeper.properties
  # Ctrl+B, D to detach


  ── Step E: Start Kafka Broker ──
  tmux new -s kafka
  cd ~/kafka
  bin/kafka-server-start.sh config/server.properties
  # Ctrl+B, D to detach


  ── Step F: Verify Kafka is healthy ──
  cd ~/kafka
  bin/kafka-topics.sh --list --bootstrap-server localhost:9092

  ✔ Should show: vehicle_telemetry_topic
     (Topic persists across restarts — no need to re-create it)


  ── Step G: Start Consumer ──
  tmux new -s consumer
  cd ~/omniroute
  source venv/bin/activate
  python telemetry_consumer.py
  # Ctrl+B, D to detach


  ── Step H: Run Producer ──
  tmux new -s producer
  cd ~/omniroute
  source venv/bin/activate
  python data_producer_scripts/run_all_producers.py
  # Enter: y

  ✔ Done! Pipeline is running again.


  ── Quick Restart Cheat Sheet (copy-paste) ──
  # Run these one after another:

  tmux kill-server 2>/dev/null
  rm -rf ~/omniroute/data/raw/telemetry/*

  tmux new -d -s zookeeper 'cd ~/kafka && bin/zookeeper-server-start.sh config/zookeeper.properties'
  sleep 5
  tmux new -d -s kafka 'cd ~/kafka && bin/kafka-server-start.sh config/server.properties'
  sleep 5
  tmux new -d -s consumer 'cd ~/omniroute && source venv/bin/activate && python telemetry_consumer.py'
  sleep 3
  tmux new -d -s producer 'cd ~/omniroute && source venv/bin/activate && python data_producer_scripts/run_all_producers.py'

  # Then attach to producer to enter 'y':
  tmux attach -t producer

  ⚠️ NOTE: The cheat sheet starts everything in background tmux sessions.
     The last command attaches to producer so you can type 'y'.
